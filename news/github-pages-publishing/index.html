無料のGitHub Pagesで、ブラウザゲームを公開する手順

ブログ2026年11月3日NEW

「3秒即断RPG」は、GitHub Pagesという無料の仕組みで公開しています。サーバーを借りる費用はかかりません。この記事では、HTMLとJavaScriptだけで作ったブラウザゲームを、GitHub Pagesで公開するまでの流れと、運用の中で気づいた点をまとめます。プログラミングの経験が少ない方でも追えるように、専門用語は、そのつど説明します。

GitHub Pagesとは

GitHubは、ファイルを保存して管理するための、無料のサービスです。そのうちGitHub Pagesは、保存したHTMLなどのファイルを、そのままWebサイトとして公開してくれる機能です。向いているのは、サーバー側で処理を行わない「静的なサイト」です。

「3秒即断RPG」は、ゲームの処理をすべて、遊んでいる人の端末の中で行っています。会員登録も、データの保管もありません。到達したエンドの記録も、端末の中にだけ保存されます。そのため、静的なサイトとして公開できます。

公開までの流れ

  1. GitHubのアカウントを作ります。無料です。
  2. 新しいリポジトリ(ファイルを入れる箱)を作ります。
  3. ゲームのファイルを、リポジトリにアップロードします。パソコンやスマートフォンのブラウザから、ファイルを画面に置く形で行えます。
  4. リポジトリの「Settings」から「Pages」を開き、公開元を選びます。「Deploy from a branch」を選び、ブランチ(mainなど)とフォルダを指定します。
  5. 数十秒から数分待ちます。公開が完了すると、サイトのアドレスが表示されます。

初期のアドレスは、「アカウント名.github.io/リポジトリ名」という形になります。独自のドメインを使う場合は、別の設定が必要です。

更新の仕組み

ファイルを差し替えて保存(コミット)すると、公開内容が自動で更新されます。この処理は、リポジトリの「Actions」の画面に、「pages build and deployment」という名前で記録されます。緑のチェックが成功の印で、赤い×が失敗の印です。「3秒即断RPG」の場合は、1回の更新が、20〜30秒ほどで終わっています。

運用で気づいた点

  • ブラウザからのアップロードには、1回に扱えるファイル数に上限があります。「3秒即断RPG」は、1回の更新が100ファイルを超えることがあるため、分けて反映しています。
  • 更新を続けて反映すると、公開の処理が重なって、失敗することがあります。実際に、「前の公開が進行中のため、今回の公開ができない」という趣旨のエラーが出ました。サイトが壊れたわけではありません。前の処理が緑のチェックになってから、次を反映するのが安全です。
  • 失敗した処理は、その画面の「Re-run all jobs」で、再実行できます。
  • 更新の直後は、端末に残った古い表示が出ることがあります。確認する時は、再読み込みをします。

費用と制限

GitHub Pagesの利用に、料金はかかりません。公式のヘルプには、公開するサイトの大きさ、月ごとの転送量、公開処理の回数に、目安の上限があると書かれています。上限は、変更される場合があるため、最新の内容は、GitHubの公式ヘルプでご確認ください。

また、ゲームのように、サーバー側で動く機能(ログインや、データの集計など)が必要な場合は、GitHub Pagesだけでは足りません。その場合は、別のサービスを組み合わせることになります。

向いている人

小さなブラウザゲームや、紹介のページを、費用をかけずに公開したい方に向いています。一方で、アクセスが多くなった時の対応や、運営上のサポートは、有料のサービスに比べて限られます。まずは、無料で公開して、様子を見る形が現実的です。
